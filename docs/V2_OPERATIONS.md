# دليل تشغيل ميزان v2

## الحسابات على النسخة الحية
- **الحساب التجريبي (بيانات وهمية لستة أشهر):** `demo@mizan-erp.sa` / `Demo@2026` — زر "تعبئة بيانات الحساب التجريبي" في صفحة الدخول. لإعادة الضبط: الإعدادات ← البيانات التجريبية ← حذف ثم تحميل.
- **المدير العام للنظام:** سجّل بالبريد المحدد في `SUPER_ADMIN_EMAIL` ليظهر قسم "إدارة النظام والتراخيص" (إصدار مفاتيح الترخيص، إيقاف/تمديد المنشآت، الدخول لأي منشأة).

## دورة العمل اليومية للمحاسب
1. **الأصناف والعملاء والموردون** — أو استيراد الأرصدة الافتتاحية: قيد افتتاحي من القيود اليومية (مع تفصيل العملاء/الموردين بالطرف) + أرصدة المخزون من شاشة الجرد.
2. **المبيعات**: عرض سعر ← أمر ← فاتورة (ترحيل = قيد + خصم مخزون + QR/XML) ← سند قبض مخصص على الفاتورة. المرتجع بإشعار دائن من داخل الفاتورة.
3. **المشتريات**: أمر شراء ← فاتورة مورد (زيادة مخزون بالمتوسط المرجح + ضريبة مدخلات) ← سند صرف. مرتجع مشتريات من داخل الفاتورة.
4. **نقطة البيع**: فتح وردية بنقدية افتتاحية ← بيع (نقدي/شبكة/مختلط/آجل لعميل مسجل) ← مرتجع من فاتورة ← إغلاق الوردية بعدّ النقدية (يُرحّل العجز/الزيادة ويورَّد النقد للصندوق الرئيسي).
5. **المصروفات** بحساب المصروف وطريقة الدفع (فوري أو آجل على مورد) مع ضريبة المدخلات.
6. **الأصول**: تسجيل الأصل ← تشغيل الإهلاك الشهري ← الاستبعاد.
7. **نهاية الفترة الضريبية**: ضريبة القيمة المضافة ← مراجعة النموذج ← تسجيل التقديم (قيد تسوية) ← تسجيل السداد. ثم قفل الفترة من السنوات والفترات.
8. **نهاية السنة**: إقفال السنة المالية (قيد إقفال يرحّل النتيجة إلى الأرباح المبقاة) — قابل لإعادة الفتح.
9. **قبل أي تقرير رسمي**: التقارير ← فحص التطابق (10 فحوص آلية).

## أدوات المحاسب الإضافية
- **الشيكات**: شيك مستلم (أوراق القبض/العميل) ← إيداع ← تحصيل (البنك/أوراق القبض) أو مرتجع (يعيد فتح الفواتير). شيك صادر (المورد/أوراق الدفع) ← صرف (أوراق الدفع/البنك) أو إلغاء.
- **التسوية البنكية**: تأشير الحركات المطابقة لكشف البنك، إدخال رصيد الكشف، اعتماد التسوية.
- **القيود الدورية**: قوالب مصروفات/قيود/فواتير تُنفَّذ تلقائياً في موعدها (فحص كل ساعة) أو يدوياً.
- **حد الائتمان**: منع الفاتورة الآجلة التي تتجاوز حد العميل، مع تجاوز للمالك/المدير يُسجَّل في التدقيق.
- **مشاركة الفاتورة**: رابط عام للقراءة والطباعة (واتساب/بريد) من صفحة الفاتورة.
- **استيراد Excel** للأصناف والعملاء والموردين بقالب جاهز، و**نسخة احتياطية JSON** كاملة من الإعدادات.
- **تقارير إضافية**: تحليل المصروفات، المندوبون، تقدير الوعاء الزكوي مع ترحيل مخصص الزكاة.

## نقطة البيع دون اتصال
التطبيق يُثبَّت على جهاز الكاشير (PWA) ويحفظ الكتالوج والوردية. عند انقطاع الإنترنت يستمر البيع محلياً بإيصال مؤقت، وتُرحَّل العمليات تلقائياً بترتيبها ووقتها الأصلي عند عودة الاتصال (مزامنة آمنة من التكرار). الشرط الوحيد: فتح الوردية أثناء الاتصال.

## الرواتب
الموظفون (أساسي/سكن/نقل/بدلات، الجنسية للتأمينات، IBAN) ← مسير شهري بمكافآت/خصومات ← ترحيل قيد الاستحقاق (رواتب + بدلات + تأمينات المنشأة / رواتب مستحقة + تأمينات مستحقة) ← صرف الرواتب من البنك ← ملف WPS للبنك.

## الفوترة الإلكترونية — المرحلة الثانية
الإعدادات ← الفوترة الإلكترونية: اختر المرحلة الثانية والبيئة (Sandbox للتجربة، Simulation للمحاكاة، Production للفعلي) ← توليد المفاتيح وCSR ← OTP من بوابة فاتورة ← إصدار شهادة الامتثال ← فحص الامتثال على 4 فواتير (مبسطة، قياسية، إشعار دائن، إشعار مدين) ← إصدار شهادة الإنتاج. بعدها كل فاتورة بيع تُوقّع وتُرسل تلقائياً، والمعلق يُرسل من الشاشة ذاتها.

## النشر
`git push` إلى `main` ينشر تلقائياً على Railway (خدمة `mizan-api`، الجذر `apps/api`): البناء `npm install --include=dev && npm run build`، التشغيل `npm start` (يطبّق هجرات `db/migrations` ثم يستمع). فحص الصحة `/api/health`.

قاعدة PostgreSQL على Railway؛ يُنصح بتفعيل النسخ الاحتياطي اليومي من لوحة Railway (Volume Backups) أو `pg_dump` مجدول.
