# Mizan ERP | ميزان — Phase 0

هذا مستودع بداية (Greenfield) بُني وفق `docs/` أدناه استجابةً لمواصفة "MIZAN ERP — Final Master Prompt". هذه الجلسة أنجزت مرحلتين إضافيتين: إنشاء فترات محاسبية جديدة، وفاتورة ضريبية كاملة ببيانات مشترٍ.

## المرحلة الأولى: إنشاء فترات محاسبية جديدة (Sprint 31)

حتى هذه الجلسة، كانت فترة محاسبية واحدة فقط تُزرَع تلقائيًا عند إنشاء المنظمة، بلا وسيلة لفتح فترة جديدة.

- **`POST /organizations/:id/periods`** جديد — يتحقق من صحة التواريخ ومن عدم تداخل الفترة الجديدة مع أي فترة قائمة لنفس المنظمة.
- **مُختبر حيًا**: فترة جديدة لعام 2028 أُنشئت → القائمة أظهرت فترتين → محاولة فترة متداخلة رُفضت (400) → **بيع POS حقيقي رُحِّل فعليًا داخل الفترة الجديدة**.

## المرحلة الثانية: فاتورة ضريبية كاملة (Tax Invoice) ببيانات مشترٍ (Sprint 31)

مولِّد XML من الجلسة السابقة كان يغطي فقط الفاتورة المبسطة. أُضيف الآن:

- **`buildTaxInvoiceXml()`** جديدة — تُعيد استخدام منطق البائع/الأسطر/الضريبة، وتضيف: الرمز الفرعي "01" بدل "02" (BR-KSA-06)، وكتلة بيانات المشترٍ الكاملة المطلوبة إلزاميًا لهذا النوع (BR-10، BR-KSA-42، BR-KSA-63).
- **مُختبر حيًا**: فاتورة بمشترٍ كامل البيانات → فُحصت بمحلل XML مستقل → `InvoiceTypeCode name="0100000"` صحيح → كتلة المشترٍ ظهرت بكل حقولها الصحيحة.
