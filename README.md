# Mizan ERP | ميزان — واجهة تشغيل عربية ونقطة بيع

هذا مستودع بداية (Greenfield) بُني وفق `docs/` أدناه استجابةً لمواصفة "MIZAN ERP — Final Master Prompt". هذه الجلسة أخرجت المشروع لأول مرة إلى بنية تحتية حقيقية خارج بيئة العمل: **GitHub + Railway + PostgreSQL حقيقي + أول هجرة Prisma فعلية**.

## بنية البيانات الحالية

- مستودع GitHub حقيقي: `mostafasalem3500-prog/mizan-erp`.
- مشروع Railway حقيقي مع PostgreSQL 16 يعمل فعليًا.
- هجرات Prisma قياسية تُطبَّق تلقائيًا عند بدء Railway.
- بيانات الهوية والعملاء والموردين والأصناف وPOS والقيود والفترات محفوظة في PostgreSQL.
- فواتير المبيعات والمشتريات والمصروفات والأصول والمدفوعات وأرصدة المخزون تستخدم مستودعات Prisma دائمة عند تفعيل `USE_REAL_PRISMA_DB=true`.
- **إثبات حاسم**: تحميل محركات Prisma الثنائية نجح بالكامل على Railway — الحجب طوال الجلسات السابقة كان خاصًا ببيئة العمل تلك فقط، وليس قيدًا في المشروع.

## الكود — النتيجة الفعلية الحالية: 32 Test Suites، 280 اختبارًا ناجحًا

## نقطة البيع الجديدة

- كتالوج بصري سريع ببحث وتصنيفات وصور منتجات، مع ترتيب البطاقات بالسحب والإفلات وحفظ الترتيب محليًا.
- سلة بيع فورية تدعم تغيير الكميات والحذف، وتحسب ضريبة القيمة المضافة 15% والإجمالي لحظيًا.
- طرق دفع نقدي ومدى وبطاقة، وقوالب طباعة حراري 80 مم وA4 ومبسّط.
- فاتورة ضريبية قابلة للطباعة مع QR للمرحلة الأولى، ومعاينة قبل الطباعة.
- إضافة صنف سريع من داخل شاشة البيع، واختصارات لوحة المفاتيح F2 للبحث وF5 للإتمام.
- تصميم RTL متجاوب يحافظ على بنية النظام ويقدم هوية أكثر احترافية وسهولة للمستخدم غير المحاسبي.
- حساب كل مبالغ نقطة البيع بالهللات الصحيحة لمنع فروق التقريب مثل `43.13` مقابل `43.13`.
- استوديو فاتورة محفوظ يدعم القالب، لونين، الخط، المحاذاة، شكل الجدول، موضع QR، والحقول الظاهرة.

## الدورة المحاسبية والترحيل الآلي

- قيود المبيعات ونقطة البيع والمشتريات والمصروفات والمدفوعات والمخزون والأصول والتحويلات تمر عبر محرك ترحيل واحد يفرض توازن المدين والدائن وعدم التكرار.
- ميزان المراجعة وسجل القيود والأستاذ العام يقرؤون الآن من PostgreSQL الحقيقي في بيئة الإنتاج.
- مركز دورة محاسبية عربي يعرض حالة الفترة، ميزان المراجعة، صافي النتيجة، ومصدر كل قيد آلي.
- إقفال مرحلي قابل لإعادة الفتح، وإقفال نهائي ينشئ قيدًا آليًا لتصفير الحسابات المؤقتة وترحيل الربح أو الخسارة إلى حساب الأرباح المبقاة `3200`.
- الفترات المقفلة تمنع القيود الجديدة وعكس القيود القديمة، مع تسجيل إجراءات الإقفال في سجل التدقيق.

## وضع العرض العام المؤقت

يمكن تفعيل الدخول إلى حساب البيانات التجريبية دون كلمة مرور عبر متغير البيئة:

```bash
PUBLIC_DEMO_MODE=true
```

المسار لا يلغي المصادقة أو صلاحيات الخادم؛ بل يصدر رمز JWT موسومًا بوضع العرض للحساب التجريبي الثابت. أعد القيمة إلى `false` فور انتهاء العروض العامة. لا تستخدم هذا الوضع لبيانات منشأة حقيقية.

## حدود صادقة لا تزال قائمة

- حفظ مستند المصدر وقيده المالي ليس بعدُ معاملة PostgreSQL واحدة في كل الوحدات؛ مفاتيح عدم التكرار والتعويض الآلي تقللان الخطر، لكن المعاملة الذرية الكاملة ما زالت مطلوبة.
- لا ختم تشفيري ZATCA حقيقي، لا PIH متسلسل حقيقي.
