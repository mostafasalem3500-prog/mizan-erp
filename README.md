# ميزان ERP | Mizan ERP v2

نظام محاسبي سحابي متكامل (SaaS) للمنشآت السعودية: محاسبة عامة، مبيعات ومشتريات، نقاط بيع بالورديات، مخزون بالمتوسط المرجح، أصول ثابتة وإهلاك، تقارير مالية كاملة، إقرار ضريبة القيمة المضافة بنموذج الهيئة، والفوترة الإلكترونية (المرحلة الأولى والثانية).

- **الرابط الحي:** https://mizan-api-production-7c00.up.railway.app
- **المستودع:** `mostafasalem3500-prog/mizan-erp` · **الاستضافة:** Railway (خدمة `mizan-api` + PostgreSQL 16)

## نموذج التشغيل

سحابي متعدد الشركات والمستخدمين مع نظام تراخيص بسيريال:

| | |
|---|---|
| التسجيل | أي منشأة تسجّل نفسها وتحصل على فترة تجريبية (`TRIAL_DAYS`، افتراضياً 14 يوماً) |
| بعد الانتهاء | النظام يتحول إلى **قراءة فقط** حتى تفعيل مفتاح ترخيص |
| الترخيص | المدير العام يصدر مفاتيح `MZN-PRO-XXXXX-…` (خطة + مدة بالأشهر + عدد مستخدمين) من لوحة إدارة النظام، والعميل يفعّلها من الإعدادات ← الاشتراك |
| المدير العام | أول مستخدم يسجّل، أو البريد المحدد في `SUPER_ADMIN_EMAIL` |
| الأدوار | مالك، مدير نظام، محاسب، مندوب مبيعات، كاشير، أمين مستودع، مشاهد/مدقق |

لماذا سحابي وليس نسخة على جهاز العميل؟ المرحلة الثانية من الفوترة الإلكترونية تتطلب اتصالاً حياً بمنصة فاتورة للإبلاغ والاعتماد، إضافة إلى النسخ الاحتياطي المركزي والتحديث الفوري لجميع العملاء ومنع النسخ غير المرخص.

## البنية

```
apps/api/
  db/migrations/*.sql     هجرات SQL تُطبَّق تلقائياً عند الإقلاع (جداول v1 القديمة تُنقل إلى schema "legacy" دون حذف)
  src/db                  اتصال PostgreSQL (pg) + مساعد استعلامات + معاملات و savepoints
  src/lib                 أخطاء، أرقام عشرية (decimal.js)، رموز الضريبة، مصادقة JWT وصلاحيات الأدوار
  src/accounting          دليل الحسابات السعودي، محرك الترحيل (الكاتب الوحيد للقيود)، المخزون بالمتوسط المرجح
  src/services            الفواتير (عرض سعر ← أمر ← فاتورة ← إشعار)، السندات، المصروفات، الأصول، نقاط البيع، الإقفال، التقارير، البيانات التجريبية
  src/zatca               UBL 2.1 XML، الهاش وسلسلة PIH وعداد ICV، توقيع ECDSA secp256k1، QR (TLV)، عميل Fatoora API
  src/routes              REST API (/api/auth, /api/admin, /api/…)
  web/                    واجهة React + Vite عربية RTL (تُبنى إلى web/dist وتُخدم من نفس الخادم)
legacy/                   كود الإصدار الأول (NestJS/Prisma) محفوظ للرجوع
```

### ضمانات محاسبية

- كل مستند يُرحَّل داخل معاملة واحدة مع قيده وحركة مخزونه؛ أي فشل يلغي الكل.
- المحرك يرفض القيود غير المتوازنة، والترحيل على حسابات رئيسية/موقوفة، والتواريخ داخل فترات أو سنوات مقفلة — ويؤكد ذلك **trigger** في قاعدة البيانات.
- القيود المرحّلة لا تُعدَّل؛ التصحيح بقيد عكسي أو إشعار دائن مرتبط بالفاتورة الأصلية.
- المخزون بكمية **وقيمة** لكل (صنف، مستودع) فلا تنشأ فروق تقريب بين كرت الصنف وحساب المخزون.
- شاشة **فحص التطابق** تقارن آلياً: ميزان المراجعة، الميزانية، العملاء، الموردين، المخزون، ضريبة المخرجات والمدخلات، الأصول ومجمع الإهلاك.

### أدوات إضافية للمحاسب
شيكات مستلمة/صادرة بدورة كاملة مع طباعة الشيك، تسوية بنكية، قيود ومستندات دورية بجدولة تلقائية، رقابة حد الائتمان، رابط مشاركة عام للفاتورة، تفقيط المبالغ، استيراد Excel، نسخة احتياطية JSON، تقارير تحليل المصروفات والمندوبين، تقدير الوعاء الزكوي، قائمة دخل مقارنة، أرباح مراكز التكلفة، موازنات تقديرية مع تقرير الموازنة مقابل الفعلي، تنبيهات المحاسب.

### التجارة الخارجية والتسعير والبنوك
تعدد العملات (أسعار صرف بتاريخ، مستندات وسندات بعملة أجنبية، أرباح/خسائر فروق عملة عند السداد)، ضريبة الاستيراد كالتزام للجمارك مع سدادها، تحميل تكاليف الشحن والجمارك على تكلفة المخزون، قوائم أسعار للعملاء (ثابتة بشرائح كمية أو خصم) تعمل في الفواتير ونقطة البيع، واستيراد كشف الحساب البنكي مع مطابقة تلقائية.

### المخزون المتقدم والتحصيل
عبوات متعددة للصنف (كرتون/علبة بباركود وسعر) في الفواتير ونقطة البيع، طباعة ملصقات الباركود (EAN-13/Code128)، اقتراحات إعادة الطلب مع إنشاء أوامر الشراء لكل مورد، وشاشة تحصيل للذمم المتأخرة برسائل واتساب/بريد وسجل متابعة وكشوف حساب جماعية، وإرسال المستندات بالبريد عند ضبط SMTP.

### الدفعات والصلاحية
تتبع رقم الدفعة وتاريخ الانتهاء للأصناف القابلة للتلف، صرف FEFO تلقائي في المبيعات ونقطة البيع مع منع بيع المنتهي، تقرير الصلاحية والإتلاف وتنبيهاته.

### الفروع المتعددة
الفرع بُعد محاسبي على كل قيد (من مستودع المستند أو الفرع المختار أو فرع المستخدم)، مستودعات مرتبطة بالفروع، تحويلات بين الفروع عبر «جاري الفروع»، فلتر الفرع في القوائم المالية، وتقرير مقارنة أداء الفروع وبطاقة في لوحة المؤشرات.

### ربط متاجر سلة وزد
سلة وزد على خط واحد: استقبال Webhooks سلة الموقعة: كل طلب يصبح فاتورة مرحّلة بقيدها ومخزونها وختم الهيئة، تسوية المدفوعات الإلكترونية في حساب وسيط، تحصيل الدفع عند الاستلام عند التوصيل، إشعار دائن تلقائي للإلغاء، مزامنة الأصناف، وسجل أحداث مع إعادة المعالجة.

### التكامل والربط
واجهة برمجية REST عامة `/api/v1` بمفاتيح API (قراءة/كتابة) لربط المتاجر الإلكترونية والمواقع والأنظمة: الأصناف والمخزون والعملاء، واستقبال الطلبات كفواتير مرحّلة دون تكرار، وسندات القبض؛ إشعارات Webhooks موقّعة HMAC مع سجل وإعادة إرسال؛ وبوابة عميل برابط خاص لكشف الحساب والفواتير.

### الرواتب والموارد البشرية
مسيرات رواتب بالتأمينات الاجتماعية وملف WPS، إجازات وأرصدتها، سلف الموظفين بخصم تلقائي، مخصصات نهاية الخدمة والإجازات شهرياً وفق نظام العمل السعودي (م. 84/85/109) بسجل فرعي لكل موظف، وتصفية نهائية بمخالصة مطبوعة.

### ضريبة القيمة المضافة والفوترة الإلكترونية

- الفئات: خاضع 15%، نسبة صفر، صادرات، معفى، خارج النطاق، استيراد مدفوع بالجمارك، احتساب عكسي.
- إقرار بنموذج الهيئة (البنود 1–14) مع مطابقة الأستاذ العام، وقيد تسوية عند التقديم، وقيد سداد.
- المرحلة الأولى: QR بخمس خانات على كل فاتورة. المرحلة الثانية: XML موقّع، PIH/ICV، QR بتسع خانات، إصدار شهادتي الامتثال والإنتاج عبر OTP، إبلاغ المبسطة واعتماد القياسية، إعادة إرسال المعلق.

## التشغيل المحلي

## نسخة سطح المكتب (ويندوز)
- المثبّت: https://github.com/mostafasalem3500-prog/mizan-erp/releases/latest (`Mizan-ERP-Setup-<version>.exe`).
- عند أول تشغيل يختار المستخدم: **سحابي** (يفتح الخادم المستضاف) أو **محلي** (قاعدة PostgreSQL مدمجة في `%APPDATA%\Mizan ERP\pgdata`، يعمل بلا إنترنت، تجربة 30 يومًا).
- الترخيص المحلي: مفاتيح `MZD-…` موقّعة Ed25519 تُصدر من لوحة المدير (خيار «مفتاح لنسخة سطح المكتب») وتُفعّل دون إنترنت. المفتاح الخاص في متغير `LICENSE_SIGNING_KEY` فقط.
- التحديث التلقائي من إصدارات GitHub (electron-updater).
- البناء: ارفع `version` في `apps/desktop/package.json` ثم شغّل workflow «Desktop (Windows)» (أو ادفع وسم `v*`)؛ يبني على windows-latest وينشر الإصدار.
- محليًا: `cd apps/desktop && npm ci && npm run dist:win` (على لينكس يتطلب wine).
- المثبّت غير موقّع رقميًا → يظهر تحذير SmartScreen («مزيد من المعلومات ← التشغيل على أي حال»).

## الجولة الرابعة عشرة — البحث والفلترة وكشوف الحسابات في كل الشاشات، وصور الأصناف
- **بحث وفلترة وفرز في كل القوائم**: العملاء والموردون (حالة الرصيد/المتأخر/تجاوز الحد/المدينة/النوع)، الأصناف (التصنيف/النوع/المخزون/الصورة/الحالة)، المستندات (الطرف/الفترة/المتأخرة/حالة الهيئة)، السندات (الطريقة/الصندوق/الحالة/الطرف)، المصروفات (الحساب/نقدي-آجل)، القيود (الحساب/الطرف/المبلغ)، دليل الحسابات، الشيكات، القوالب الدورية، الأصول، الموظفون والإجازات والسلف والتصفيات، الدفعات، التحصيل، التسوية البنكية، تقييم المخزون وحركاته، قوائم الأسعار، إعادة الطلب، المستخدمون، سجل التدقيق، ميزان المراجعة وأعمار الديون وتحليل المبيعات. البحث يتجاهل الهمزات والتاء المربوطة والأرقام الهندية، وعدّاد «n من m» وزر مسح الفلاتر، والفرز بالضغط على رأس العمود، والإجماليات تتبع الفلتر.
- **كشوف الحسابات**: كشف العميل/المورد بملخص (أول/آخر المدة، مدين/دائن، المتأخر، حد الائتمان)، فلتر الفرع، بحث، كشف تفصيلي بأصناف الفواتير، تبويب المستندات المفتوحة وأعمارها، وروابط للمستند الأصلي. كشف أي حساب بفلتر الفرع والطرف ومركز التكلفة. متاح من: العملاء، الموردين، المستندات وشاشة الفاتورة، السندات (كشف الطرف + كشف صندوق/بنك)، المصروفات (كشف حساب المصروف)، القيود، دليل الحسابات، ميزان المراجعة (اضغط الحساب)، أعمار الديون، الشيكات، الأصول، التسوية البنكية، وتبويب «كشوف الحسابات» في التقارير (عميل/مورد/حساب/صندوق/صنف/موظف).
- **صور الأصناف**: من نقطة البيع (زر «🖼 صور الأصناف»: تحديد الأصناف ثم رفع صورها) ومن شاشة الأصناف (تحديد ثم «صور الأصناف»). رفع فردي/جماعي، سحب وإفلات، الكاميرا من الجوال، لصق Ctrl+V، تنزيل وحذف، ومطابقة تلقائية لاسم الملف مع الرمز/الباركود/الاسم. الصور تُضغط في المتصفح (600px JPEG) وتُقدَّم من `/api/media/products/:id?v=` بتخزين مؤقت، وتعمل دون اتصال في نقطة البيع.
- إصلاحات: خلايا الإجراءات في الجداول، الأوقات بالتقويم الميلادي، صفحة إدارة النظام لغير المدير العام.

## الجولة الخامسة عشرة — مركز التقارير وجاهزية التشغيل
- **مركز التقارير** (`/reports-center`): 58 تقريراً مفصّلاً في 11 مديولاً — المالية (قائمة دخل شهرية، ميزانية مقارنة، تغيرات حقوق الملكية، النسب المالية، حركة الحسابات، أستاذ عام تفصيلي، أرصدة الأطراف، مراكز التكلفة، ملخص القيود)، المبيعات (تحليل بأي بُعد، سجل، بنود، مرتجعات، عروض وأوامر، مبيعات يومية بطرق الدفع، تحصيلات، غير مسدد)، المشتريات (تحليل، سجل، بنود، تطور الأسعار، مرتجعات، مدفوعات، غير مسدد)، المخزون (حركة وارد/صادر، سجل حركات، حسب المستودع، حالة المخزون وأيام التغطية، راكد، دوران، جرد وتحويلات، قيمة بالتصنيف)، نقطة البيع (ورديات، كاشير، أصناف، ساعات، طرق دفع، مرتجعات)، الخزينة (أرصدة، حركة، سندات، ملخص سندات، شيكات، فروق عملة)، المصروفات (سجل، تحليل، مصفوفة شهرية)، الرواتب (ملخص، قسائم، تكلفة الموظفين، التأمينات، السلف)، الأصول (سجل، جدول إهلاك)، الضريبة (تفصيل مخرجات/مدخلات، شهري)، المتاجر الإلكترونية (طلبات، تحويلات).
- كل تقرير: فلاتر متعددة (فترة، فرع، مستودعات، تصنيفات، طرف، صنف، حساب، مركز تكلفة، مستخدم، حالة، قناة، طريقة دفع… اختيار متعدد)، تجميع حسب بُعد، مؤشرات علوية، رسم بياني، فرز، بحث داخل النتائج، إجماليات، Excel وطباعة، نقر للمستند الأصلي، رابط قابل للمشاركة بفلاتره، وفلاتر محفوظة.
- API: `GET /api/reports/catalog`, `GET /api/reports/run/:key?...`, `GET /api/reports/dimension/:key`.
- **جاهزية التشغيل**: بطاقة في لوحة المؤشرات (`GET /api/readiness`) تتابع خطوات ما قبل التشغيل الفعلي (بيانات المنشأة، الأرصدة الافتتاحية، الأصناف، دورية الإقرار، حذف البيانات التجريبية، الفوترة الإلكترونية…).
- **اختبار الحركات**: سكربت مطابقة بين التقارير والأستاذ العام (المبيعات = قائمة الدخل، المخزون = التقييم = حساب المخزون، الصناديق = ميزان المراجعة، الضريبة = الإقرار، الأطراف = الذمم، الرواتب = المسيرات، الإهلاك = مجمع الإهلاك…) — كلها متطابقة.

## الجولة السادسة عشرة — واجهة الجمعيات الخيرية (رابط مستقل `/charity`)
- **رابط منفصل** `https://<النطاق>/charity` بهوية خاصة (اسم الجمعية، الشعار، رقم الترخيص) وقائمة مخصصة، يعمل على نفس الحسابات والقيود والمستخدمين، مع زر انتقال للبرنامج الأساسي وخيار فتح الواجهة تلقائياً بعد الدخول.
- **الشاشات:** لوحة المؤشرات، سندات القبض والتبرعات، العملاء المتبرعون، التحصيل، تحصيل دخول الأموال اليومية (مع إقفال الصندوق وقيد العجز/الزيادة)، عروض الأسعار، المصروفات (سندات صرف نقدي/شيك/تحويل)، طلبات الصرف FIN-001 بمسار اعتماد (تقديم ← مراجعة مالية ← اعتماد ← صرف)، مسير المصروفات (صرف جماعي + كشف للتوقيع + Excel للبنك)، المستفيدون، الرواتب، المشاريع والبرامج (مركز تكلفة لكل مشروع، أموال مقيدة)، الموازنة التقديرية (مقدّر مقابل فعلي ونسخ من سنة سابقة)، قائمة الأنشطة، أرشيف الفواتير والمستندات، القوالب الجاهزة A4، إعدادات الجمعية (المعتمدون والتوقيعات وإعادة تسمية القوائم).
- **القيود:** سند القبض: من ح/ الصندوق أو البنك إلى ح/ إيرادات الجمعية (43xx: تبرعات عامة، دعم ومنح، مساهمات تأسيسية، إيرادات برامج، زكاة، تبرعات مقيدة، اشتراكات). سند الصرف: من ح/ مصروفات البرامج والمساعدات (55xx) إلى ح/ الصندوق أو البنك. الحسابات تُضاف تلقائياً عند أول استخدام، والإلغاء بقيد عكسي.
- **القوالب A4:** طلب صرف مالي FIN-001، سند صرف نقدي FIN-002، سند صرف مالي FIN-003، سند صرف شيك/تحويل FIN-004، سند قبض مالي FIN-005، إيصال استلام مبلغ FIN-006 — قابلة للتحكم (العنوان، الرمز، الأقسام، النصوص، حقول إضافية، الألوان، الختم، نسختان)، تُطبع فارغة أو معبأة من السند مع المبلغ كتابةً، وتُضبط تلقائياً على صفحة A4 واحدة.
- الجداول الجديدة: `charity_settings, charity_projects, charity_receipts, charity_disbursements, charity_requests, charity_batches, charity_budget_lines, charity_day_closings` (الترحيل 014).

## الجولة السابعة عشرة — العهد المالية والمشتريات والاسترداد وقوالب جديدة للجمعيات
- **العهد المالية** (`/charity/custody`): طلب ← مراجعة ← اعتماد بمبلغ معتمد ← صرف (سند صرف + قيد: من ح/ العهد المالية المؤقتة 110390 إلى الصندوق/البنك) ← تسوية بسطور مصروفات مؤيدة بمستنداتها (قيد: من ح/ المصروفات + الصندوق للمتبقي إلى ح/ العهد، أو صرف الفرق لصاحب العهدة بعد الاعتماد)، مع تنبيه العهد المتأخرة عن موعد التسوية، وإلغاء التسوية بقيد عكسي.
- **طلبات الشراء ومحاضر الاستلام** (`/charity/purchases`): طلب بأصناف وكميات وأسعار وضريبة ← مراجعة المشتريات والمالية ← اعتماد ← أمر شراء ← محضر استلام بالكميات المطلوبة/المستلمة وحالة الأصناف ونتيجة الفحص.
- **طلبات الاسترداد** (`/charity/refunds`): طلب بسبب الاسترداد وبيانات الآيبان ← مراجعة ← اعتماد بالمبلغ الموافق عليه ← تنفيذ بسند صرف (من ح/ الإيراد المختار إلى الصندوق/البنك).
- **مستحقات المتطوعين**: سند الصرف بصفة «متطوع» يحمل البرنامج والفترة التطوعية ويطبع إقرار الاستلام.
- **قوالب A4 جديدة**: طلب شراء FIN-007، محضر استلام مشتريات FIN-008، طلب استرداد FIN-009، طلب عهدة FIN-010، تسوية عهدة FIN-011، إقرار مستحقات متطوع FIN-012، وتحديث إيصال استلام مبلغ FIN-006 (رقم القيد، المسلِّم، طريقة «أخرى»). جداول أصناف في القوالب، والنماذج الطويلة تُطبع على صفحتين مرقمتين بخط مقروء أو تُضغط في صفحة واحدة اختيارياً.
- لوحة المؤشرات والأرشيف يشملان العهد وطلبات الشراء والاسترداد. الترحيل 015.

## الجولة الثامنة عشرة — طباعة كل نموذج فارغاً، وهوية الجمعية
- شاشة **«النماذج الفارغة للطباعة»** (`/charity/blank-forms`): القوالب الاثنا عشر مصنفة (القبض، الصرف، المشتريات، العهد والاسترداد) بمعاينة مصغرة، طباعة أي نموذج فارغاً بعدد نسخ، تحديد عدة نماذج وطباعتها معاً، أو نسخة من كل النماذج.
- نافذة الطباعة في كل شاشة فيها اختيار **«معبأ بالبيانات / فارغ للتعبئة اليدوية»** مع عدد النسخ، وزر «نموذج فارغ» في سندات القبض والصرف وطلبات الصرف والعهد والمشتريات والاسترداد.
- اسم الجمعية ورقم ترخيصها يُؤخذان افتراضياً من النماذج المرسلة: «جمعية ريادة العطاء لخدمة الإنسان بالعسيلة الأهلية» — ترخيص 1000888600 (الترحيل 016)، وتبقى قابلة للتعديل من إعدادات الجمعية.

## الجولة التاسعة عشرة — الكفالات، التبرعات العينية، المتطوعون، الشهادات والتنبيهات
- **الكفالات** (`/charity/sponsorships`): كافل من المتبرعين ← مكفول من المستفيدين، بقسط شهري/ربع/نصف سنوي/سنوي ومدة اختيارية؛ حساب الأقساط المستحقة والمسددة والمتأخرة والقسط القادم؛ «تحصيل» يصدر سند قبض مصدره «كفالة» (حساب 4309 إيرادات الكفالات) مرتبطاً بالكفالة؛ تذكير واتساب للكافل المتأخر؛ «مسير صرف الكفالات» ينشئ مسودة مسير لكل مستفيد بنصيبه الشهري (حساب 5507).
- **التبرعات العينية** (`/charity/inkind`): أصناف بكميات وقيمة (متوسط مرجح) وحد إعادة طلب؛ استلام تبرع عيني (من ح/ 110391 مخزون التبرعات العينية إلى ح/ 4308 تبرعات عينية بالقيمة التقديرية) وصرف مساعدات عينية للمستفيدين (من ح/ 5506 إلى ح/ 110391)؛ إلغاء بقيد عكسي مع حماية من إلغاء استلام وُزّع منه.
- **المتطوعون** (`/charity/volunteers`): سجل المتطوعين ومهاراتهم، ساعات التطوع لكل برنامج، المستحقات المصروفة لهم، وشهادة تطوع.
- **قوالب جديدة**: سند استلام تبرع عيني FIN-013، محضر صرف مساعدات عينية FIN-014، شهادة شكر وتقدير للمتبرع CRT-01 (من سجل المتبرع بإجمالي سنة أو كل الفترة)، شهادة تطوع CRT-02 — بتصميم شهادات بإطار مزخرف، وكلها متاحة فارغة أيضاً (أصبحت 16 قالباً).
- **مركز التنبيهات** في لوحة المؤشرات: عهد متأخرة التسوية، كفالات متأخرة، أيام بتحصيل نقدي غير مقفلة، طلبات صرف/شراء/استرداد معلقة أكثر من 3 أيام، مسيرات مسودة، بنود موازنة تجاوزت 90%، أصناف عينية تحت حد الطلب، مستفيدون بلا آيبان.
- **واتساب**: شكر المتبرع مع بيانات سند القبض، تذكير الكافل، شكر المتطوع.
- الترحيل 017.

## الجولة العشرون — تنفيذ قائمة ملاحظات ERP (المحاسبة والجمعيات وكل الفروع)
- **ملف العميل/المورد** (`/customers/:id`، `/suppliers/:id`): مؤشرات وتبويبات (الفواتير، عروض الأسعار، الإشعارات، المدفوعات، كشف الحساب، الأرصدة الافتتاحية) وإجراءات: فاتورة، عرض سعر، إشعار دائن/مرتجع، دفعة، رصيد افتتاحي (قيد مقابل حقوق الملكية الافتتاحية)، تعيين مندوب، شروط الدفع وحد الائتمان، إيقاف/تفعيل (الموقوف لا تُصدر له مستندات جديدة).
- **الفاتورة وعرض السعر**: تعديل المسودة، وللمرحّلة تصحيح عبر إشعار دائن + نسخة جديدة (متوافق مع زاتكا)، نسخ، تحويل عرض السعر لفاتورة، ملاحظات، ربح الفاتورة، حركات المخزون وإذن صرف/استلام مخزني، إشعار خصم مالي دون أصناف. عرض السعر يُفتح بعد الحفظ كصفحة مستند.
- **صفحة الصنف** (`/products/:id`): الأرصدة بالمستودعات، ربح المبيعات، حركة المخزون، وإجراءات تعديل/تحويل/جرد/إتلاف (قيد خسائر مخزون)/رصيد افتتاحي/حذف (أو إيقاف إن وُجدت حركات).
- **الحسابات البنكية والخزائن** (`/treasury`): أرصدة وحركات، تعديل البيانات البنكية (IBAN)، إنشاء حساب، تحويل بين الحسابات مع رسوم وضريبة مدخلات ومنع السحب على المكشوف، إلغاء التحويل بقيد عكسي، تعطيل الحساب عند رصيد صفري فقط.
- **شجرة الحسابات** تعرض القيود داخل الشجرة، و**صفحة قيد** لكل قيد (`/journals/:id`) قابلة للطباعة وPDF.
- **تقارير**: ورقة الجرد (مع الجرد الأعمى)، ملخص عمليات المخزون، المبيعات حسب المندوب.
- **PDF** لكل التقارير والفواتير وعروض الأسعار والقيود والسندات ونماذج الجمعيات.
- **نوافذ الإنشاء لا تُغلق بالنقر خارجها**، وتطلب تأكيداً عند الإغلاق إن وُجدت بيانات مدخلة.
- واجهة الجمعيات: الخزائن والحسابات البنكية وصفحة القيد وPDF.
