# ميزان لايت — نسخة الأساسيات لأجهزة أندرويد

نقطة بيع ومحاسبة أساسية من نظام ميزان: تعمل على الجهاز بلا إنترنت وبلا تسجيل دخول، والبيانات محفوظة محلياً.

## الإصدار 1.1.0
- **الورديات**: فتح وردية بعدّ النقدية في الدرج، وكل فاتورة ومرتجع وسند يُسجَّل في ورديته. عند الإغلاق يحسب البرنامج المتوقع في الدرج (الافتتاح + النقدي الداخل − الخارج) ويقارنه بالمعدود؛ العجز أو الزيادة بقيد على حساب جديد 5210 «عجز وزيادة الصندوق». تقرير مؤقت (X) وتقرير إغلاق (Z) للطباعة الحرارية، وخيار «البيع يتطلب وردية مفتوحة».
- **المستخدمون برمز سري**: المالك ثم الكاشيرية (4–6 أرقام، محفوظة مجزّأة SHA-256 بملح لكل مستخدم). يُطلب الرمز عند الفتح، وزر قفل في الشريط العلوي. الكاشير يرى البيع والمرتجع والوردية والعملاء فقط، ولا يصل للمحاسبة والتقارير والإعدادات ولا يعدّل الأصناف أو المشتريات أو السندات. كل فاتورة وقيد باسم من أصدره، وتقرير الوردية يفصل المبيعات حسب المستخدم. بلا مستخدمين يبقى الجهاز بمستخدم واحد بلا قفل كما في 1.0.
- **مرتجع المشتريات**: من فاتورة المشتريات، كلياً أو جزئياً، نقداً أو بنكاً أو خصماً من حساب المورد. إشعار مدين؛ القيد من ح/ المورد أو النقدية إلى ح/ المخزون وح/ ضريبة المدخلات، وتُعاد تكلفة الصنف. لا يُرجع ما بيع، ولا تُلغى فاتورة عليها مرتجع.
- **قراءة الباركود بالكاميرا**: زر الكاميرا في نقطة البيع يضيف الأصناف للسلة واحداً بعد الآخر، وفي نموذج الصنف يملأ خانة الباركود. يستخدم BarcodeDetector إن وُجد في WebView، وإلا محلّلاً مدمجاً لـ EAN-13 وEAN-8 وUPC-A يقرأ الإطار مرتين قبل القبول. صلاحية الكاميرا تُطلب عند أول استخدام، ولصفحة التطبيق فقط.
- باركود الأصناف التجريبية صار برقم فحص EAN-13 صحيح، وبيانات 1.0 تُرقّى تلقائياً (المستخدمون والورديات والحساب الجديد).
- الاختبارات: `test/lite11.test.js` (المحرك، 60 فحصاً) و`test/ui_test2.py` (الشاشات على الجوال والكمبيوتر، 40 فحصاً، بكاميرا وهمية تعرض باركوداً)، إضافة إلى `engine.test.js` و`ui_test.py` السابقين.

## المحتوى
- `src/core.js` المحرك المحاسبي (قيد مزدوج، المبالغ بالهللة أعداداً صحيحة، QR الهيئة للمرحلة الأولى، التفقيط).
- `src/ui1.js` `ui2.js` `ui3.js` `ui4.js` `print.js` `style.css` الواجهة وقوالب الطباعة.
- `build.js` يجمع كل شيء في ملف واحد `dist/index.html` وينسخه إلى `android/app/src/main/assets/`.
- `android/` مشروع أندرويد (WebView، بلا مكتبات خارجية) — الحد الأدنى أندرويد 5.0.
- `test/engine.test.js` اختبار المحرك (45 فحصاً) و`test/lite11.test.js` (60)، `test/ui_test.py` اختبار الواجهة على أربعة مقاسات (128 فحصاً) و`test/ui_test2.py` (40).
- بناء الـAPK: `.github/workflows/android-lite.yml` في جذر المستودع.

## البناء محلياً
    npm install && npm test && npm run build
    cd android && gradle assembleRelease      # يحتاج Android SDK (compileSdk 34) و JDK 17

## مفتاح التوقيع
- مخزن المفاتيح `android/keystore/mizan-lite.p12` (الاسم المستعار `mizanlite`) محفوظ هنا **مشفَّراً** بكلمة مرور عشوائية طويلة ليست في المستودع.
- كلمة المرور توضع مرة واحدة في سر المستودع `LITE_KEYSTORE_PASSWORD`. بدونها يُبنى الملف بتوقيع تجريبي (`-test`).
- كل تحديث يجب أن يُوقَّع بالمفتاح نفسه ليُثبَّت فوق النسخة السابقة دون فقد البيانات — لا تستبدل الملف ولا تفقد كلمة المرور.

## الربط مع النسخة الأصلية
- التطبيق يقرأ `apps/lite/version.json` من الفرع `main` (الإعدادات ← التحديث) ويعرض رابط تنزيل الإصدار الأحدث.
- لإصدار جديد: ارفع الرقم في `package.json` و`VERSION` داخل `src/core.js` و`version.json` معاً، ثم شغّل «Android Lite» مع release.
- إصدارات لايت بوسم `lite-vX.Y.Z` و`--latest=false` حتى لا يتأثر التحديث التلقائي لنسخة سطح المكتب.

## لم يُتحقق منه بعد
- قراءة الكاميرا داخل WebView على جهاز فعلي، ووجود BarcodeDetector فيه (اختُبر المحلّل المدمج بكاميرا وهمية في Chromium فقط).
- بناء Gradle والتشغيل على جهاز فعلي (كود Java مفحوص بالمترجم مقابل واجهات أندرويد 34 فقط).
- الطباعة على طابعة حرارية فعلية وعلى طابعات أجهزة الدفع المدمجة (تحتاج خدمة طباعة على الجهاز أو SDK الشركة المصنّعة).
